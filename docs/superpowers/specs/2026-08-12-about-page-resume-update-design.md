### 技术栈磁贴

`data-skill` 与 template id 可重命名以匹配新主题，须与 `about.js` 的 `skill-detail-` + `data-skill` 约定一致。建议：

| data-skill | 标题 | 副标题 |
|------------|------|--------|
| rag | RAG | FAQ 命中 92%+ · 答对率 88% |
| agent | Agent | LangGraph · 最多 8 轮 |
| classify | 文本分类 | BERT 94% · F1 0.93 |
| compress | 模型压缩 | 量化 / 蒸馏 / 剪枝 |
| prompt | Prompt + AI 编程 | Bad Case 迭代 · Cursor |

### 详情（template 正文）

数字只用来自新简历的值。禁止再写：Dify、Coze、MCP、代码成功率 95%+、召回率 90%+、蒸馏 8.3×、体积 -62%、20 万级文本、效率 +40%、智能投顾、金融资讯。

**RAG**  
FAQ 高置信就直接返回，没命中再走向量检索 + 生成。文档按章节切块，表格尽量整块留；做过 PDF 父子分块，大约 2000 块，BGE-M3 写入 Milvus。检索按零件、文档类型、缺陷类型过滤，跨件误召回降了大约 40%。FAQ 命中准确率 92%+，误命中压在 3% 以内；自建 120 题评测，整体答对率从 75% 提到 88%。生成侧用 LangChain 接 Qwen，要求强制引用，标准数值不够就拒答。

**Agent**  
用 LangGraph 做多轮排查：接案、查槽位、追问或调工具、出建议、结案。下一步按槽位和规则走，不是写死流水线；同一 case 跨轮合并槽位，最多 8 轮。尺寸类缺测量值就强制追问，不给硬结论。工具有分类建议、标准检索、相似案例检索。有证据才给排查建议，并写明只辅助、不替代判废；证据都没有就转人工，不编数据。对外是 FastAPI 接口，另外有 CLI demo。

**文本分类**  
不合格现象是自由文本，先归到外观、尺寸、装配、功能这几类。样本 5000 条（训练 4000 / 测试 1000）。对比过 TF-IDF + 随机森林、FastText、BERT。BERT 准确率 94%、F1 0.93，比随机森林基线（F1 0.82）高 11 个百分点。

**模型压缩**  
在 BERT 上做过动态量化、蒸馏（学生模型是 BiLSTM）和 L1 剪枝。效果和体积一起看，更倾向蒸馏到 BiLSTM，当轻量部署的备选。

**Prompt + AI 编程**  
Prompt 会写指令约束、输出格式和角色，也会加上引用要求和拒答条件，按 Bad Case 小步改。开发上用 Cursor、Claude Code 拆需求、改代码、定位报错，主要用来加速 Agent / RAG / 分类相关模块。

## 错误处理与测试

本页为静态模板，无表单、无外部 API。验证方式：

1. 本地打开 `/about`，确认简介、5 块磁贴、详情展开/收起、爱好、邮箱。
2. 点每个磁贴，标题与详情与上表一致；再点同一块应收回。
3. 全文搜索旧关键词（Dify、Coze、智能投顾、gmail 等）应无命中（gmail 仅允许从本页移除；其他页若仍有邮箱则不在本次范围）。
4. 需要时跑 `python scripts/build_static.py`，确认 `dist/about/index.html` 含新文案与新邮箱。
