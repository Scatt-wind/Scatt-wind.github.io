## 从两个案例看见机器学习

学完线性回归和 KNN 之后，我最大的感受是：机器学习并不是「背会几个算法名」就够了，而是一套可以复用的工程流程——**数据准备 → 特征处理 → 模型训练 → 效果评估 →（可选）超参调优 → 预测未知数据**。

两个入门案例恰好覆盖了监督学习的两大分支：

| 案例 | 任务类型 | 预测目标 | 核心算法 |
|------|---------|---------|---------|
| 波士顿房价预测 | **回归** | 连续数值（房价） | 线性回归 / SGD |
| 鸢尾花分类 | **分类** | 离散类别（花种） | K 近邻（KNN） |

表面上看，一个用 Excel 表格、一个用 sklearn 内置数据集；一个输出房价数字、一个输出 0/1/2 类别标签。但跑通代码之后我发现，它们的骨架几乎一模一样。理解了这一点，后续学决策树、SVM、神经网络时，就不会每次都从零开始摸索。

---

## 通用机器学习流程

两个案例共享同一条 pipeline，可以用下图概括：

```mermaid
flowchart LR
    dataLoad[数据加载] --> split[训练测试划分]
    split --> featureEng[特征工程_标准化]
    featureEng --> train[模型训练]
    train --> eval[模型评估]
    eval --> tune[超参调优_可选]
    tune --> predict[未知数据预测]
```

逐步对照代码，我总结了以下关键原则：

| 步骤 | 波士顿房价 | 鸢尾花分类 |
|------|-----------|-----------|
| 数据加载 | `pd.read_excel` 读取本地表格 | `load_iris()` 加载内置数据集 |
| 训练/测试划分 | `test_size=0.2, random_state=304` | 参数完全一致 |
| 特征标准化 | 训练集 `fit_transform`，测试集 `transform` | 同上；KNN 基于距离计算，标准化尤为关键 |
| 模型训练 | `LinearRegression` / `SGDRegressor` | `KNeighborsClassifier` |
| 模型评估 | MSE / MAE / RMSE | `accuracy_score` |
| 超参调优 | `GridSearchCV` 搜索 `eta0`、`max_iter` | `GridSearchCV` 搜索 `n_neighbors` |

有两个细节我一开始容易忽略，后来反复踩坑才记住：

1. **`random_state=304`**：固定随机种子，保证每次划分结果一致，方便对比不同算法和参数的效果。
2. **标准化不能泄露测试集信息**：`StandardScaler` 只能在训练集上 `fit`，测试集和新数据只能调用 `transform`。如果把测试集也 fit 进去，评估结果会虚高，上线后模型表现会大幅缩水。

波士顿案例中的标准写法：

```python
transformer = StandardScaler()
x_train = transformer.fit_transform(x_train)
x_test = transformer.transform(x_test)
```

鸢尾花案例用了完全相同的模式，这说明 sklearn 的 API 设计是高度一致的——换任务类型，流程不用推倒重来。

## 案例一：波士顿房价预测 — 回归的三个层次

这个案例用三个函数层层递进，带我走完了回归任务从「能用」到「好用」的完整路径。

### 基础线性回归（`linear_ml`）

第一步是最朴素的 `LinearRegression()`。它通过最小二乘法直接求解最优权重，适合样本量不大、特征维度适中的场景。

数据准备很直接：用 `iloc` 把最后一列作为目标值 `y`，其余列作为特征 `x`，然后按 8:2 划分训练集和测试集。

评估时我同时看了三个指标，各自有不同的含义：

- **MSE（均方误差）**：对大误差惩罚更重，一个离谱的预测会把分数拉得很差。
- **MAE（平均绝对误差）**：更直观，可以理解为「平均预测偏了多少个单位」。
- **RMSE（均方根误差）**：对 MSE 开方，量纲与房价一致，更容易向业务方解释。

```python
y_pred = model.predict(x_test)
print(f'MSE: {mean_squared_error(y_test, y_pred)}')
print(f'MAE: {mean_absolute_error(y_test, y_pred)}')
print(f"RMSE：{root_mean_squared_error(y_test, y_pred)}")
```

跑完之后，我学会了不只看一个数字，而是结合指标含义判断模型「错在哪」。

### SGD 随机梯度下降（`sgd_ml`）

第二个函数把求解器换成了 `SGDRegressor`。问题没变，但优化方式变了——不再一次性算闭式解，而是分批抽样、迭代更新权重。

这里我第一次认真理解了几个超参数：

- `max_iter`：最大迭代轮数，相当于「学几遍」。
- `eta0`：学习率初始值，推荐范围 `[0.001, 0.01]`。
- `learning_rate='invscaling'`：学习率随迭代次数逐渐衰减，避免后期震荡。

```python
model = SGDRegressor(
    max_iter=1000, shuffle=True, random_state=304,
    learning_rate='invscaling', eta0=0.001
)
```

我的体会是：小数据集上线性回归和 SGD 效果可能差不多，但 SGD 的思想更重要——当数据量上到百万级，闭式解算不动的时候，迭代优化才是出路。先跑通 `LinearRegression` 做 baseline，再换 SGD 对比，是更稳妥的学习路径。

### 交叉验证 + 网格搜索（`sgd_cv_ml`）

第三个函数引入了 `GridSearchCV`，在 `eta0` 和 `max_iter` 的组合空间里自动寻找最优超参：

```python
param_dict = {
    "max_iter": [500, 700, 1000],
    "shuffle": [True],
    "random_state": [304],
    "learning_rate": ["constant"],
    "eta0": [0.001, 0.005, 0.01]
}
model = GridSearchCV(estimator=SGDRegressor(), param_grid=param_dict, cv=3)
model.fit(x_train, y_train)
print("最优超参组合: ", model.best_params_)
```

`cv=3` 表示三折交叉验证：数据被分成三份，轮流拿两份训练、一份验证，取平均得分最高的参数组合。这比手动试参数系统得多。

代码注释里有一条很实用的工程建议：**网格搜索通常只需要跑一次**。找到 `best_params_` 之后，把最优参数写回模型定义，然后把 GridSearch 相关代码注释掉即可。调参是研发阶段的工作，不应该每次预测都跑一遍搜索。

## 案例二：鸢尾花分类 — 从探索到预测

### 先探索，再建模（EDA）

鸢尾花案例比房价案例多了一个 `eda()` 函数，这是我学到的很重要的一课：**分类任务不要上来就调参，先看数据长什么样。**

通过散点图观察不同特征与类别的关系，我发现：

- 花萼长度 vs 花萼宽度：三类花混在一起，区分度一般。
- 花瓣长度 vs 花瓣宽度：三类之间界限清晰，是更有判别力的特征。

```python
sns.lmplot(data=df, x="petal length (cm)", y="petal width (cm)",
           fit_reg=False, hue="target")
```

**可视化是特征工程的第一步**: 如果花瓣特征已经能明显分开三类，那 KNN 的效果自然不会差。

### KNN 的核心逻辑

KNN（K-Nearest Neighbors）的思路很直觉：看新样本周围最近的 K 个邻居属于哪一类，少数服从多数。

```python
model = KNeighborsClassifier(n_neighbors=3)
model.fit(x_train, y_train)
```

`n_neighbors=3` 意味着参考距离最近的 3 个样本「投票」决定类别。我的理解是：

- **K 太小**（如 K=1）：模型对噪声极度敏感，容易过拟合，像一个只听一个人的意见就做决定的人。
- **K 太大**：决策边界过于平滑，可能把不同类别混在一起，造成欠拟合，像开了一场过于「和稀泥」的会议。

所以 K 的值需要在「敏感」和「稳定」之间找平衡，这正是网格搜索要解决的问题。

### 未知数据预测 — 部署时最容易遗漏的一步

案例最后演示了用训练好的模型预测三朵「从未见过」的花，这一步看似简单，却最容易在生产环境中出错：

```python
unknown_data = [[5.1, 3.5, 1.4, 0.2], [6.1, 2.8, 4.7, 1.2], [5.9, 3.0, 5.1, 1.8]]
unknown_data = transformer.transform(unknown_data)  # 必须用训练时的 scaler
unknown_data_pred = model.predict(unknown_data)
```

关键在第二行：**新数据只能 `transform`，不能重新 `fit`**。如果忘了这步，特征的尺度和训练时不一致，KNN 算出的距离就完全不可信。我把这当作部署 checklist 的第一条。

### 进阶：网格搜索最优 K 值

在 [交叉验证网络搜索在鸢尾花分类中的应用] 中，进一步用 `GridSearchCV` 在 `n_neighbors` 的 `[3, 5, 7, 9, 11]` 范围内搜索最优值：

```python
param_dict = {"n_neighbors": [i for i in range(3, 12, 2)]}
model = GridSearchCV(estimator=knn_model, param_grid=param_dict, cv=3, verbose=1)
model.fit(x_train, y_train)
print("最优超参组合: ", model.best_params_)
print("最优超参得分: ", model.best_score_)
```

鸢尾花数据集很小，手动试几个 K 值也能找到不错的结果。但养成用交叉验证自动选参的习惯，到了更复杂的数据集上会省很多时间。具体准确率以本地运行结果为准，但通常在较高的水平（鸢尾花是 sklearn 的「/hello world」数据集）。

## 回归 vs 分类：我的对比心得

跑完两个案例后，我把差异和共性整理成下面这张表：

| 维度 | 回归（波士顿房价） | 分类（鸢尾花） |
|------|------------------|--------------|
| 预测目标 | 连续值（如 24.5 万美元） | 离散标签（0/1/2 对应三个品种） |
| 算法思路 | 线性回归：找一条全局最优拟合线 | KNN：找局部最相似的邻居投票 |
| 核心评估指标 | MSE / MAE / RMSE（越小越好） | 准确率 accuracy（越大越好） |
| 特征工程侧重 | 关注量纲统一、多重共线性 | 距离类算法对特征尺度极其敏感，标准化是刚需 |
| 主要调参对象 | 学习率 `eta0`、迭代次数 `max_iter` | 邻居数 `n_neighbors` |
| 数据探索 | 相关性分析、残差分布 | 散点图、类别可视化（EDA） |
| 共同工具 | `train_test_split`、`StandardScaler`、`GridSearchCV` | 完全相同 |

最大的共性在于 **sklearn 统一的 API 风格**：`fit` 训练、`predict` 预测、`score` 评估。学会一个案例的套路，另一个案例几乎只是换几个 import 和评估指标。

最大的差异在于 **怎么判断模型好不好**：回归看「偏了多少」，分类看「分对了多少」。选错指标，就像用体重秤去量身高——数字有了，结论毫无意义。

## 总结与实践建议

回顾这段学习历程，我总结了五条可以立刻用上的实践建议：

1. **先跑通 baseline，再叠加复杂度。** 波士顿案例从 `LinearRegression` → `SGDRegressor` → `GridSearchCV` 的递进顺序很值得借鉴。不要一上来就网格搜索，先把最简单的模型跑通，确认数据和 pipeline 没有问题。

2. **固定 `random_state`，方便公平对比。** 两个案例都用了 `random_state=304`，这样换算法时训练集和测试集的划分完全一致，对比才有意义。

3. **分类先 EDA，回归看指标含义。** 鸢尾花教会我「先看图再建模」；波士顿教会我「不只看一个数字，要理解 MSE、MAE、RMSE 各自代表什么」。

4. **超参搜索是一次性工作。** 找到 `best_params_` 后写回模型、注释掉搜索代码。调参属于研发阶段，不应嵌入日常预测流程。

5. **预测新数据时，预处理 pipeline 必须与训练一致。** `transformer.transform(new_data)` 这行代码，是练习和真实部署之间的分界线。

两个入门案例虽然数据简单、算法经典，但它们完整覆盖了监督学习的两大分支和通用工程流程。在此基础上，还可以继续探索 [正则化案例] 中的过拟合与 Lasso/Ridge，以及更系统的交叉验证策略。

机器学习的路还很长，但至少这两个案例让我确信：**框架是通用的，差异主要在问题定义和算法选择。** 把这条主线抓住，后面的学习会轻松很多。
